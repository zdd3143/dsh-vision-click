# 测试说明

## 怎么跑

```powershell
# 1) 打开测试窗口（保持在前台约 90 秒，够跑一轮）
powershell -NoProfile -ExecutionPolicy Bypass -File tests/target-window.ps1

# 2) 另开一个终端，跑端到端测试
node tests/run-click-test.mjs
```

测试直接 `import` 插件的 `index.js`，用一个最小的假 `ctx`（工具注册表、logger、attachments）
把它跑起来，因此不需要启动 DSH 本体。

期望输出结尾是 `all checks passed`（31 项断言）。

## 测试窗口里有什么

| 控件 | 用来验证 |
| --- | --- |
| 三个大按钮（开始测试 / 上一步 / 下一步） | 目标文字点击、双击、右键、长按、悬停 |
| 可拖动黄色方块「拖动我」 + 「拖到这里」 | 真实拖拽（MouseDown/Move/Up，松手后 1.4 秒归位，便于重复跑） |
| 40 行列表 | 滚轮滚动 |
| 输入框（初始文字「账号」） | 键入、`ctrl+a` 全选、覆盖输入、退格、回车 |
| 两个同名「重复标签」 | 歧义时必须拒绝点击 |

每次交互都会把状态栏文字改成可观察的结果（`状态：已开始第 N 次`、`状态：已拖动到 x,y`、
`状态：输入框里有 N 个字`），所以断言的是**事实**而不是实现细节。

## 断言分组

1. **感知**：`gui_look` 能返回行索引；OCR 能读到「开始测试」。
2. **点击**：目标点击成功、像素复核判定有反应、状态文字变成「已开始…」；重复点击后计数递增。
3. **歧义**：`重复标签` 命中两处 → 拒绝点击并列出候选。
4. **批处理**：`gui_do` 三步（点击 → 等待 → 点击）全部完成。
5. **悬停**：`hover: true` 执行了，但没有按下按钮（状态文字不变）。
6. **右键**：执行了，但没有触发左键处理逻辑。
7. **长按**：`holdMs: 700` 松手后按钮仍被触发。
8. **拖动**：执行成功、画面变化、状态栏出现「已拖动」。
9. **滚轮**：`amount: 5` 执行后列表内容变化。
10. **键盘**：`gui_type` 键入后屏幕上出现对应文字；`ctrl+a` + 再输入完成覆盖；退格、回车正常；
    `gui_do` 能混排键盘步骤。

## 视觉模型兜底（可选）

需要先跑起 Ollama 与 UI-TARS 模型（见 [VISION.md](VISION.md)）：

```powershell
node tests/run-vision-test.mjs
```

它用 `visionMode: "always"` 强制走模型路径，断言：点击成功、`source === "vision"`、
语义型目标（"the yellow draggable block"）也能落到对应区域、吸附不会粘到无关文字。

## 常见问题

- **卡住不结束**：测试会启动常驻 PowerShell 进程；脚本结束时 `dispose()` 会杀掉它们。
  若中途手动 Ctrl+C，可能留下 `powershell.exe`，手动结束即可。
- **断言「找不到某段文字」**：先确认测试窗口在最前面。测试窗口自带 90 秒的前台保持，
  但如果中途点了别处，OCR 会去读别的窗口。
- **OCR 偶尔漏字**：Windows OCR 对某些字体/配色会漏掉最后一个字符（例如把「下一步」读成「下一」）。
  这正是插件设计里「低置信只列出、不自动点」的原因；测试中对应断言允许「点击成功」或「明确拒绝」。
- **端口/权限**：测试不联网、不写注册表，只用 `%TEMP%\dsh-vision-click-test` 存附件。

## 加一个用例

1. 在 `tests/target-window.ps1` 里加一个会改变状态栏文字的控件；
2. 在 `tests/run-click-test.mjs` 里用 `call('gui_xxx', {...})` 触发它；
3. 用 `check(label, condition, detail)` 断言可观察结果（优先断言文字变化，而不是像素值）。
